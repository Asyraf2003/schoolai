`docs-private/engineering` workflow, specialized for ambitious SchoolAI UI/UX:

cinematic scenes or models.

## 5. Decisions

- Canonical terms are viewport tier, cinematic scene, render frame, and surface.
- No fixed number of WebGL scenes is implied.
- Create target folders only while migrating a proven owner.
- Preserve existing runtime until replacement proof passes.
- Migrate one surface/capability per accepted blueprint.
- Route entries own composition; migrated leaf modules become imports, not
  permanent independent Vite entries.
- Production can never import or route to lab code.
- Labs use a separate local/testing route and Vite graph when implemented.
- Promotion is a fresh production patch; rejected labs are removed.
- Full source migration begins only after a read-only baseline.

## 6. Target structure

Normative target and dependency direction are defined by
`../UI_UX_EXECUTION_FOUNDATION.md`.

```text
semantic Blade section
-> owned component/surface CSS
-> one surface controller
-> optional shared graphics runtime + surface scene
-> route entry
```

All six tiers share that ownership. Fluid geometry adapts between boundaries.

## 7. Locale, browser, and WebGL

- One semantic DOM/content source across ID, EN, and AR.
- ID/EN share Inter/LTR; AR uses Cairo/RTL through a narrow adapter.
- Directional meaning mirrors; neutral time/scroll/orbit does not.
- Chromium/WebKit differences use capability tests and narrow defect adapters.
- WebGL stays outside the critical path and attaches to a semantic surface.
- One renderer/context/scheduler remains default regardless of tier count.

## 8. Experiment acceptance

A lab must have one hypothesis, separate non-production graph, synthetic or
licensed local assets, measurable acceptance, expiry/removal, complete cleanup,
and no production import.

It may become production only through another owner-accepted surface blueprint
and full DOD proof.
